# Архитектура RareLauncher

## Компоненты

1. **Launcher Desktop** проверяет собственную версию, авторизует игрока, получает профиль сборки, сравнивает SHA-256 локальных файлов и скачивает только отличия.
2. **Launcher API** управляет аккаунтами, ролями, сессиями, скинами, профилями серверов, манифестами и короткоживущими игровыми билетами.
3. **Artifact storage** раздаёт неизменяемые файлы по хешу. Вначале используется локальный том, позже без изменения протокола подключается S3.
4. **Manifest builder** строит подписанный манифест из эталонной клиентской сборки.
5. **Minecraft auth mod** проверяет игровой билет при подключении и применяет UUID/профиль/текстуры аккаунта rareteam.

## Поток запуска

1. Лаунчер обновляет собственный бинарник.
2. Пользователь входит; access token короткий, refresh token ротируется.
3. Лаунчер получает профиль `minecraft-1.21.1-neoforge` и подписанный манифест.
4. Планировщик сравнивает размер и SHA-256, удаляет только явно управляемые лишние файлы и докачивает различия параллельно с возобновлением.
5. Backend выдаёт одноразовый игровой билет.
6. Лаунчер запускает Java 21 с рассчитанными аргументами и передаёт билет через локальный защищённый IPC/переменную процесса.
7. Серверный мод обменивает билет на профиль и отклоняет повторное использование.

## Границы доверия

- Пароли хешируются Argon2id.
- Refresh token хранится через системное защищённое хранилище ОС.
- Манифесты подписываются Ed25519 и проверяются до применения.
- Все файлы проверяются SHA-256 после загрузки.
- Административные маршруты требуют отдельной роли и аудируются.
- Сервер никогда не доверяет нику, UUID или скину, присланному клиентом без билета backend.
